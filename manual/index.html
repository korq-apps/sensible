Sensible User Manual

This manual is permanently installed on your system at /usr/share/sensible/manual/ and is always accessible offline from the application menu (Sensible Manual) or terminal by running sensible-manual.

Use this page for setup, desktop basics and recovery. Explore the companion chapters for why the applications are included and how to start, or terminal tools with practical recipes.

1. Welcome to Sensible

Sensible is an opinionated remix of Debian Testing (Forky) for 64-bit x86 (amd64) UEFI systems. The installed operating system is pure Debian: the UEFI boot entry is Debian, system packages come from Debian repositories, and Debian system administration standards apply throughout.

Sensible copies a prebuilt system from the ISO, without package downloads during installation. Debian packages and pinned Sensible defaults are prepared when the image is built.

This manual opens automatically on your first installed desktop login. You can reopen it from the application menu at any time. Reading it needs no network; the update and software-installation commands below do.

2. Your First Five Minutes

Follow these quick orientation steps right after logging in:

  1. Connect to Network: Use the network menu in the top-right status area (GNOME) or bottom-right system tray (KDE) to connect to Wi-Fi or Ethernet.
  2. Update Package Lists & System: Open a terminal and run standard Debian updates: 
    sudo apt update && sudo apt full-upgrade
  3. Reboot on Core Updates: If a new kernel, systemd, or graphics driver is installed during updates, restart your system to engage the new components.
  4. Check Device Firmware: If your vendor provides updates through the Linux Vendor Firmware Service (LVFS), check with fwupd: 
    sudo fwupdmgr refresh
sudo fwupdmgr get-updates
sudo fwupdmgr update
  5. Explore Applications: Open Software (GNOME) or Discover (KDE) to browse and manage installed tools and Flatpaks.

3. Desktop Basics & Shortcuts

GNOME Edition

The GNOME edition is configured for a focused, fluid workflow:

  • Super (Windows key): Tap to open the Activities Overview, search applications, and switch dynamic workspaces.
  • Clipboard Shortcuts (keyd): GNOME includes a system-level key remapping service (keyd) mapped for Mac-style clipboard muscle memory:
    Shortcut Action Terminal Behavior
    Super + C Copy selection Sends Ctrl+Insert (safe: does not send SIGINT interrupt signal)
    Super + V Paste clipboard Sends Shift+Insert (paste in applications that support it)
    Super + X Cut selection Sends Ctrl+X
    Terminal Protection
    In traditional Linux terminals, Ctrl+C interrupts running processes. Super+C sends Ctrl+Insert instead; copying depends on the application's support for that shortcut. Check commands before pasting them into a terminal.
  • Workspaces: Use the Activities Overview to switch workspaces. Available touchpad gestures depend on your hardware and session settings.

KDE Plasma Edition

The KDE edition follows traditional desktop conventions:

  • Standard bottom taskbar, application launcher menu, and system tray.
  • Window switching via Alt + Tab.
  • Standard Linux shortcut bindings (keyd is not enabled on KDE).

Screen Locking & Session Defaults

  • Idle Timeout: The screen locks automatically after 5 minutes of inactivity on both GNOME and KDE.
  • Resume Lock: KDE explicitly locks on resume; GNOME follows its desktop defaults.
  • Automatic Login: If selected during an encrypted installation, automatic desktop login engages after unlocking the LUKS2 disk at boot. Unencrypted installs always require password login.

Saved Passwords: Passwords and Keys (GNOME) & KDE Wallet

Your apps save passwords and login tokens (browser logins, mail, chat) in a keyring, encrypted separately from your disk and screen lock. On GNOME you manage it in the Passwords and Keys app; on KDE, in KDE Wallet.

With password login (the default), you never see a keyring prompt. The password you type at the login screen unlocks the single keyring in the same step, and every app uses it. That password is the same one that unlocks the disk, so there is nothing extra to remember. Only a password entered at login can unlock the keyring: fingerprint or face login does not. Sensible’s Face Login Setup enables face recognition for unlocking an existing desktop session and, optionally, administrator commands. After a boot or logout, start the desktop with your account password; Howdy cannot replace that password login. Face unlock does not decrypt a keyring that was locked separately. Fingerprint and automatic-login settings are separate and can still leave an encrypted keyring locked. If face login was enabled with an older setup, reopen Face Login Setup and choose Turn off and set up again to apply this behavior. If you change your account password with the passwd command alone, the keyring keeps the old one and will ask for it; change your password through Settings, or update the keyring in Passwords and Keys, to keep them in step.

If a second keyring ever asks for its password (typically one named "Default Keyring", left over from a period of automatic login), tick Automatically unlock this keyring whenever I'm logged in on that prompt. GNOME then keeps that keyring's password inside your login keyring, which your login password already unlocks, so it never asks again. This is the standard GNOME mechanism and needs no merging of keyrings.

If you chose automatic login, saved passwords are not encrypted. Automatic login enters no password, so nothing can unlock an encrypted keyring; on GNOME, Sensible stores the keyring without a password so apps still work without prompting. Anyone who can reach the machine can then read those saved passwords. This is a deliberate trade for the convenience you asked for. To protect them, open Passwords and Keys and set a password on the Login keyring (you will then be asked for it once per session), or switch back to password login.

KDE first-use error: “Seems that your system has no keys suitable for encryption” comes from the KDE Wallet Service dialog that creates a new wallet. Its first page preselects Use GPG encryption, for better protection, which needs an existing OpenPGP key. For an ordinary password-backed wallet, go back and choose Classic, blowfish encrypted file, then set a non-empty wallet password; matching your account password allows password-login integration when configured. Existing wallets must not be deleted or replaced to bypass an error. KDE explains the two backends.

Keep credentials protected: Do not remove the wallet password, disable secret storage, or save your login password in a script merely to avoid prompts. A wallet password can differ from your current account password, especially after an administrator resets the account password. Treat Try Sensible as a temporary session, not a place to keep valuable credentials.

Cross-desktop first-use and unlock improvements are planned in issue #29. A disk-unlock-to-keyring path must be tested before Sensible promises it; no such new integration is shipped by this documentation update.

4. Installing Software

Sensible provides standard package management tools for Debian and Flatpak:

System Packages & CLI Tools (APT)

Use apt for system software, drivers, command-line utilities, and developer runtimes:

# Search for packages
apt search <name>

# Install packages
sudo apt install <package-name>

Graphical & Desktop Applications (Flatpak & Flathub)

Flatpak, desktop store integration and the system-wide Flathub remote (with its signing key) are preconfigured on both editions. Installation does not contact Flathub; browsing, installing and updating apps requires a network connection. No Flatpak apps or runtimes are preinstalled.

Verify the source, or add it on an older Sensible image:

# Check existing Flatpak remotes
flatpak remotes --system

# Older images only: add the system-wide Flathub source when online
sudo flatpak remote-add --system --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo

When online, browse and install desktop applications (e.g., Slack, Spotify, Discord, VS Code) directly from GNOME Software or KDE Discover. Flathub is a third-party source separate from Debian; inspect the publisher and permissions of each app.

6. Storage & Security

Disk Partitioning Model

Sensible configures a dedicated GPT layout on the target drive:

Partition Size Filesystem Mountpoint Encrypted (LUKS)
Partition 1 1024 MiB FAT32 (ESP) /boot/efi No (UEFI specification)
Partition 2 1024 MiB Ext4 /boot No (Unencrypted kernel & initramfs)
Partition 3 Remainder Btrfs or Ext4 / (root) Optional LUKS2

Root Filesystems

  • Btrfs: Structured with dedicated subvolumes:
    • @ mounted at /
    • @home mounted at /home
    • @snapshots mounted at /.snapshots
    • @var_log mounted at /var/log
    • @swap mounted at /swap (uncompressed swapfile host)
  • Ext4: Traditional single root filesystem with fast_commit enabled.

Swap, Compressed RAM & Hibernation

Swap is configured as a dedicated swapfile inside root (matching RAM capacity). When LUKS is enabled, the swapfile is located inside the encrypted container and is protected at rest.

Ahead of that file, Sensible enables compressed RAM swap (zram, sized at half of physical RAM, lz4 compression, priority 100). The kernel fills it first and only spills to the disk swapfile (priority 10) when it is full, so routine memory pressure costs little disk I/O. The logical size is not the RAM it uses: the compressed footprint is what counts. Hibernation is different: the memory image is written only to the disk swapfile, which is why that file stays RAM-sized. If the ZRAM service ever fails, the system still boots and swaps to the file.

swapon --show          # /dev/zram0 above the swapfile, with priorities
zramctl                # compressed vs. uncompressed data in RAM
systemctl status zramswap
Secure Boot & Hibernation
The installer configures hibernation resume parameters regardless of Secure Boot state. Kernel lockdown under Secure Boot blocks the unverified hibernation image; the restriction is in the kernel, not an installer configuration switch. With Secure Boot disabled, successful hibernation still depends on hardware and drivers and must be tested on your machine.

Unencrypted /boot & Secure Boot Chain

/boot is unencrypted; Plymouth unlocks the root filesystem during boot. The installer stages Debian's signed shim and GRUB for Secure Boot. Signature enforcement depends on Secure Boot being enabled in firmware; it does not encrypt the files in /boot.

With Secure Boot enabled, the firmware must trust the certificate signing Debian's shim. Some Windows PCs disable Microsoft's third-party UEFI CA by default; Lenovo documents Allow Microsoft 3rd Party UEFI CA for its Secured-core PCs. Firmware updates or resets can change that trust. This also matters after installation; see Troubleshooting.

7. Hardware & Peripherals

  • Kernel & Firmware: Debian Testing kernel with selected firmware packages for Intel, AMD, Realtek, Broadcom, MediaTek and SOF audio hardware.
  • Audio & Bluetooth: PipeWire and WirePlumber manage audio routing and Bluetooth profiles; ALSA UCM profiles, ALSA mixer tools and Cirrus/TI speaker-amplifier firmware are included. If a laptop is silent, run sensible-audio-check (see Troubleshooting).
  • Power Management: power-profiles-daemon provides integrated power modes in desktop settings. Available profiles depend on the hardware.
  • Printing & Scanning: CUPS, ipp-usb, and sane-airscan provide driverless IPP/eSCL printing and scanning support.
  • Fingerprint Support: fprintd and its PAM integration are included; enrollment requires a supported reader. Face recognition is not included.
  • Firewall: UFW denies incoming and allows outgoing traffic, with LocalSend and GSConnect/KDE Connect port exceptions on both editions. These exceptions are not limited to trusted networks. Read the sharing notes and check the active state with sudo ufw status verbose.
NVIDIA Hardware & Secure Boot
Proprietary NVIDIA modules must be signed with a trusted key to load under Secure Boot. Sensible does not automate Machine Owner Key (MOK) enrollment. If the driver fails to load, inspect the boot journal and follow Debian's signing and enrollment instructions; enrolling a key alone does not sign a module.

8. Backups & Snapshots

Disk encryption protects data when the computer is powered off or stolen, but it is not a backup. A hardware failure, filesystem corruption, or accidental deletion can still cause permanent data loss.

  • Btrfs Readiness: The Btrfs layout includes a dedicated @snapshots subvolume and isolates @swap outside snapshots. Automatic snapshots and rollback are not configured. A tool such as Snapper can be installed with APT, but still needs configuration and restore testing: 
    sudo apt install snapper
  • External Backups: Maintain regular backups of /home on external storage or remote destinations using tools like BorgBackup, Restic, or Pika Backup (available on Flathub).

9. Troubleshooting & Diagnostics

Installation Logs

The installer records detailed execution steps in /var/log/sensible-install.log. To inspect the install history:

sudo less /var/log/sensible-install.log

Common Diagnostic Commands

# Check storage devices and mountpoints
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS

# Check network interfaces
ip link

# View system journal for the current boot
journalctl -b --no-pager

# Check system hardware and services
systemctl status

No Sound, or Silent Speakers While Headphones Work

Run the built-in check as your normal user, then once more with sudo for driver and firmware detail from the kernel log:

sensible-audio-check
sudo sensible-audio-check

It prints the machine model, sound cards, codec subsystem ID and speaker amplifiers, then one PROBLEM block per finding with the command that fixes it:

  • Muted output or a muted mixer switch: sensible-audio-check --unmute unmutes the default PipeWire output and the ALSA Master and Speaker switches. The headphone switch is left alone: it is auto-muted whenever nothing is plugged in.
  • Amplifier tuning missing for this laptop: laptops with a Realtek codec and Cirrus CS35L56 speaker amplifiers (Lenovo, Dell and HP list the codec as ALC3306, ALC3287 and similar) need a tuning file named after the machine, cirrus/cs35l56-*-dsp1-misc-<id>*, which linux-firmware adds after the laptop ships. Without it the amplifiers refuse to run: internal speakers silent, headphones fine. This is the usual cause on a laptop newer than Debian's firmware snapshot, and Debian stable is often too old. Install updates and reboot: 
    sudo apt update && sudo apt full-upgrade
    If Debian has no newer firmware-cirrus yet, the report names the exact files to copy from upstream linux-firmware into /usr/lib/firmware/cirrus/.
  • Other missing firmware file: the report names the file and the Debian package that ships it (firmware-cirrus, firmware-sof-signed for Intel DSPs) with the reinstall command. Debian packages no AMD SOF DSP firmware; a board that needs it keeps that device off.
  • Speaker amplifier not bound by this kernel: with the tuning installed, a brand-new model can still lack its kernel entry. The speakers stay silent while headphones work until Debian Testing ships a kernel that knows the model; the same update command applies. The installer shows both findings on its completion screen when they affect the live session.

If the newest kernel still leaves the speakers silent, open an issue with the complete sensible-audio-check output and the lines from sudo journalctl -k | grep -iE 'cs35l|tas2|sof|hda'; the codec subsystem ID in the report is what a kernel quirk is keyed on. Redact anything private first.

Sensible No Longer Boots After a Firmware Reset or BIOS Update

A Secure Boot violation or return to the firmware menu before GRUB can indicate missing trust for Microsoft's third-party UEFI CA. Before changing firmware on a Windows machine, save its BitLocker recovery key and suspend protection if enabled, as described below. On supported Lenovo models, check Security → Secure Boot → Allow Microsoft 3rd Party UEFI CA; other models may use different names. Factory keys do not necessarily enable third-party CAs. If the setting is already enabled, check the image/media and vendor firmware guidance; revoked loaders and other boot failures can produce similar symptoms.

Temporarily disabling Secure Boot can help isolate the issue. Re-enable it after correcting trust if you want signature enforcement. A text scan of firmware certificate names cannot establish whether a loader passes signature and revocation checks.

Windows on a Second Disk

The installer targets the selected disk and also updates shared firmware boot entries, normally placing debian first. Windows on another disk can remain usable if its EFI boot files are also on a disk you keep. Start it through Windows Boot Manager in the firmware menu. Sensible does not configure Windows in GRUB; using a different boot chain can trigger BitLocker recovery depending on Windows policy. Another Linux installation using the same debian identifier can have its firmware entry affected.

  • BitLocker preparation: Before firmware changes, save the matching 48-digit recovery key off the machine. It may be in the Microsoft account used to set up Windows, held by your work/school administrator, or in a saved backup. In administrator PowerShell, use manage-bde -status C: and manage-bde -protectors -get C: to inspect the drive and its existing protectors. Keep this output private. Protection Off does not mean decrypted; check Conversion Status and Percentage Encrypted too.
  • Suspend and resume: For an encrypted, protected Windows system drive, run Suspend-BitLocker -MountPoint "C:" -RebootCount 0 before changing firmware. After the changes, boot Windows directly and promptly run Resume-BitLocker -MountPoint "C:", then verify Protection On with manage-bde -status C:. Suspension temporarily bypasses normal TPM protection and this command leaves it suspended until you resume it. See Microsoft's instructions. A recurring recovery prompt needs investigation; entering the key once is not a universal fix.
  • Wrong time in Windows: Windows normally treats the hardware clock as local time and Sensible uses UTC. To align Windows with UTC, run reg add "HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /t REG_DWORD /d 1 /f in administrator PowerShell and restart Windows. Using sudo timedatectl set-local-rtc 1 on Sensible instead can cause timezone/daylight-saving problems.
  • Windows disk mounts read-only or not at all: Fast Startup can leave NTFS hibernated. Disable it in Windows (Power Options → Choose what the power buttons do) and shut down fully. powercfg /h off also disables Windows hibernation. This does not unlock BitLocker-encrypted volumes.
Log Sanitization Reminder
When sharing diagnostic outputs online, always redact usernames, Wi-Fi networks, MAC addresses, and private file names. Never post passwords or encryption passphrases.

11. Roadmap and Validation Still Pending

The offline GNOME/KDE images, Try Sensible session, application baseline and GNOME profile are implemented, and both desktops have positive user feedback. The following work is not yet complete or proven in a release image:

  • sensible-apps: An interactive post-install tool for installing developer toolchains (Docker, GitHub CLI), additional browsers, and media software with verified signatures.
  • Desktop Profiles: Native KDE profile tuning remains planned. Both editions have passed ISO builds and console boot smoke. Targeted real-session checks remain for activation, login/lock/reboot behavior, OCR/QR, battery and multi-monitor behavior, and preservation of user changes.
  • Face Recognition: Optional Howdy-next face login has a standalone guided setup launcher with testing and rollback, documented in the source repository. Fingerprint support is already included.
  • Backups & Appearance: GNOME uses Paper icons and the Orchis GTK 3 theme, with offline alternatives and reset instructions. Native KDE appearance choices and a validated backup workflow remain follow-ups.
