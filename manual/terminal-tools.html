Terminal tools & recipes

You do not have to learn every tool. Start with a task: find a file, search its contents, inspect a directory or understand what the machine is doing.

Before you start

Open your desktop's terminal application. pwd prints the current directory; cd changes it. Examples with . search the current directory. Replace sample paths such as notes.txt with files you actually have. Your Documents folder may have a translated name.

~/ means your home directory: for example, ~/Documents is the Documents folder inside it. Leave the leading ~ outside quotation marks so the shell expands it; for a folder with spaces, write ~/"My Documents".

Shell variables are named values. A dollar sign reads one: $HOME contains your home-directory path, so echo "$HOME" prints it. Double quotes keep a value containing spaces together as one argument. This guide uses the shorter ~/ notation for home-directory paths.

A line beginning with # is a comment. A pipe (|) sends one command's output to another. Examples below do not need administrator privileges except the explicitly marked sudo examples. Searching a directory you cannot read is a reason to check the path, not automatically add sudo.

Debian calls the executables fdfind and batcat. Sensible's default interactive Bash configuration also provides fd and bat aliases, plus ls/ll/tree aliases for eza. We use the actual executable names here so examples also work without those aliases.

Your questionClassic commandSensible tool
“Where is the file with invoice in its name?”find . -iname '*invoice*'fdfind
“Which files contain this sentence?”grep -rn 'sentence' .rg
“Can I narrow this list by typing?”pipe the list into grepfzf

Classic tools first

The tools in this chapter are modern conveniences. The classic commands behind them are part of every Debian and Linux system: scripts, servers, containers, recovery shells and most online instructions use them, and they work even where Sensible's aliases are absent. Learn enough of them to read and follow instructions; use the modern tools when you are working interactively.

Each section below repeats its classic equivalent, so instructions written for either style remain usable.

Aliases only change your interactive shell
Sensible's ls, ll, tree, fd and bat aliases, and oh-my-bash's general set such as less with extra options and wget -c, apply to your own interactive Bash sessions. Scripts, sudo, other accounts and other shells run the classic programs. alias lists what is active, type ls shows what a name resolves to, and command ls -la bypasses an alias once. To stop using them, delete the lines under Sensible CLI defaults in ~/.bashrc, or the aliases=(general) entry above them; that file belongs to you and updates never rewrite it.

Essentials with no replacement

These have no modern substitute in the image and appear in almost every guide. Every example only reads or prints unless its comment says otherwise.

# Files and disk space
cp notes.txt notes-copy.txt     # copies; mv renames or moves
rm notes-copy.txt               # deletes immediately, with no trash
mkdir -p ~/Projects/demo        # creates a directory and any missing parents
du -sh ~/Documents              # space used by a folder
df -h                           # free space per filesystem
lsblk                           # disks and partitions
file notes.txt                  # what kind of file this is
tar -tzf archive.tar.gz         # lists an archive without extracting it
# Text pipelines
head -n 20 notes.txt            # first 20 lines; tail -n 20 shows the last 20
sort names.txt | uniq -c        # counts repeated lines
wc -l notes.txt                 # counts lines
cut -d ',' -f 2 data.csv        # second comma-separated column
sed 's/colour/color/g' notes.txt   # prints with a replacement; the file is unchanged
diff old.txt new.txt            # what changed between two files
# Processes, services and network
ps aux | grep -i firefox        # is a program running, and under which process id?
kill 12345                      # asks a process to stop; use the id shown by ps
systemctl status NetworkManager # state of a system service; q leaves the pager
journalctl -f                   # follows your session's log as it grows; Ctrl+C stops
sudo journalctl -b -p err       # system-wide errors since this boot; needs sudo
ip a                            # network interfaces and addresses
ss -tuln                        # listening ports
ping -c 3 debian.org            # online: is the network reachable?

Editing text: nano notes.txt opens the default terminal editor; Ctrl + O saves and Ctrl + X exits. vi is also installed for instructions that assume it; press Esc, then type :q! and Enter to leave without saving. Help: man ls opens a manual page (q quits), and ls --help prints a short summary for most commands.

fd-find → fdfind · find filenames

Why included: a concise recursive filename search, without needing to learn the longer expressions of find.

Classic equivalent: find . -iname '*invoice*' matches names regardless of case; find . -type f -name '*.pdf' lists PDF files. find also descends into hidden and Git-ignored directories, which fdfind skips by default.

# Names containing invoice, below the current directory
fdfind invoice

# PDF files below the current directory
fdfind -t f -e pdf

# A shell-style wildcard; quotes keep the shell from expanding it
fdfind -g '*.jpg'

# Search another directory; an empty pattern matches every name
fdfind -t f -e pdf '' ~/Documents

# Include hidden names when looking for Bash configuration
fdfind -H bashrc ~/

It searches names, not file contents. Patterns are regular expressions unless you use -g for wildcards. Hidden files and Git-ignored files are normally skipped; -H includes hidden entries, and -I stops respecting ignore files. These examples only list matches. Upstream guide.

ripgrep → rg · search inside files

Why included: fast recursive text search for notes, source code and logs.

Classic equivalent: grep -rn -F 'meeting notes' . and grep -rli invoice --include='*.md' .. grep searches hidden and ignored files too, and reports binary matches instead of skipping them.

# Literal text, with line numbers
rg -n -F 'meeting notes' .

# Case-insensitive search in Markdown files only
rg -n -i 'invoice' -g '*.md' .

# Print only the names of matching files
rg -l -F 'TODO' .

It normally skips hidden, ignored and binary files. -F treats the query as literal text rather than a regular expression; -i ignores case. This is not a PDF/Word content extractor. No matches returns status 1, which scripts should distinguish from an error. Upstream reference.

fzf · choose from a list

Why included: an interactive filter when remembering part of a filename is easier than reading a long list.

Classic equivalent: filter the list without interaction: fdfind -t f | grep -i invoice, or find . -type f | grep -i invoice on a system without fd.

# List regular files, then narrow the list interactively
fdfind -t f | fzf

Type fragments, use the arrow keys and press Enter to print a selection; Esc cancels. This recipe does not open or modify the selected file. It is a line-based recipe, so filenames containing newline characters need a different, NUL-delimited workflow.

When the packaged Bash integration is loaded, Ctrl + R searches command history and Ctrl + T inserts a chosen path. Inspect recalled commands before executing them; history may contain private data. Upstream guide.

bat → batcat · read text comfortably

Why included: syntax highlighting and line numbers when inspecting text files.

Classic equivalent: less notes.txt pages through a file (q quits), cat -n notes.txt prints it with line numbers, and head -n 40 notes.txt shows the first 40 lines.

batcat notes.txt
batcat --paging=never --line-range 1:40 notes.txt

The second command prints just the first 40 lines without a pager. If the first command opens a pager, use its arrow keys to move and q to quit. It is a viewer, not an editor; use Neovim or Kate (KDE) to change text. Upstream reference.

Inspect and revisit directories

eza · clearer directory listings

Why included: readable file metadata and a tree view in one tool.

Classic equivalent: ls -la for the detailed listing and find . -maxdepth 2 -type d for a two-level directory overview.

# Detailed listing, including hidden entries
eza -la

# A tree limited to two levels
eza --tree --level=2

# Git status alongside files, inside a repository
eza -la --git

Sensible's Bash aliases make ll a shortcut for the last command. Use command ls when you specifically need standard ls, particularly when following scripts or troubleshooting instructions. Upstream reference.

zoxide · jump to familiar folders

Why included: less repeated typing when you move between the same directories.

Classic equivalent: cd ~/Documents; cd - returns to the previous directory and cd alone returns home.

# First visit an existing folder normally
cd ~/Documents
cd

# In Sensible's configured Bash, jump back using part of its name
z Documents

# Show recorded directory scores and paths without changing directory
zoxide query -l -s

It learns visited directories; z is not a search of every folder on disk. Sensible initializes it in interactive Bash. A different shell needs its own upstream setup, and recorded paths may be private. Upstream guide.

Understand the system and structured data

btop · live resource monitor

Why included: a quick way to investigate a busy fan, memory pressure or a slow application. Try: run btop, look at CPU/memory usage and the process list, then press q to leave. Viewing is enough for a first investigation; do not terminate unfamiliar processes.

Classic equivalent: top, also left with q, and ps aux --sort=-%mem | head for the largest processes.

fastfetch · a system summary

Why included: a compact overview of the OS, desktop and hardware when orienting yourself or reporting an issue. Try: run fastfetch. It reports information, not a hardware health test. Review usernames, hostnames and other identifying details before sharing its output.

Classic equivalent: hostnamectl, uname -a, cat /etc/os-release, free -h and df -h each answer one part of the same question.

jq · read and filter JSON

Why included: structured inspection of JSON settings and API responses without manually scanning a single long line.

Classic equivalent: python3 -m json.tool settings.json pretty-prints; extracting one field needs jq or a short Python script.

# A self-contained example: output just the name
printf '%s\n' '{"name":"Sensible","offline":true}' | jq -r '.name'

# Pretty-print an existing JSON file
jq '.' settings.json

-r prints strings without JSON quotation marks. These examples write to the terminal and do not change the input file. JSON containing passwords or tokens still needs to be kept private. Upstream manual.

Git · keep a history of your work

Why included: version control for code, notes and configuration, with local history available offline.

# Run inside a repository you already have
git status
git diff
git log -5 --oneline

These show changed files, unstaged edits and recent commits without changing anything. A commit is a local snapshot; pushing publishes commits to a remote and needs a connection. Review changes before adding/committing them, never include credentials, and do not confuse local Git history with an independent backup.

Downloads and HTTPS support

curl · inspect or fetch a URL

Why included: a scriptable transfer tool for diagnostics and deliberate downloads.

# Online: show response headers without saving a file
curl --head https://www.debian.org/

For an intentional download, curl --fail --location --output filename URL saves the response and follows redirects. Replace both placeholders; the output file can be overwritten. Check the publisher and any provided checksum/signature. Do not pipe an unfamiliar download into a shell.

ca-certificates · the trust store

Why included: trusted certificate authorities used by tools such as curl to validate HTTPS servers. Tip: there is no app to open. If HTTPS validation fails, check the clock, network and issuer information; do not make curl -k a routine workaround. Custom organizational certificates require deliberate administrator setup.

sudo · deliberate administrator access

Why included: run a specific administrative command without remaining in a root shell.

# View the installation log; may prompt for your account password
sudo less /var/log/sensible-install.log

Press q to quit the log viewer. A password prompt normally shows no characters as you type. Use administrator access only when the task needs it; most tools in this chapter should run as your ordinary user.
